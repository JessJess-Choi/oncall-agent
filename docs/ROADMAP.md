# 로드맵 (8주 + 0주차)

가정: 퇴근 후와 주말, 주 10~15시간. 현재 주차: 0

일정이 밀리면 트레이스 뷰 UI, 시나리오 개수, Slack 연동 깊이부터 줄인다.
평가 하네스, 인용 검증, 인젝션 평가는 줄이지 않는다. 이 셋이 하네스 경험의 핵심이다.

## 0주차: 저장소 부트스트랩 (반나절~하루)
- [ ] 언어/프레임워크 확정, AGENTS.md의 해당 줄 갱신
- [ ] Makefile 골격 (`up`, `down`, `capture`, `test`, `eval`, `lock-golden`)
- [ ] GOLDEN.lock 생성·검증 스크립트 (labels + snapshots 해시, 불일치 시 평가 거부)
- [ ] `.env.example` 복사해 `.env` 작성 (키 이름은 `ONCALL_ANTHROPIC_API_KEY`)
- 완료 기준: `make test`가 빈 테스트로라도 통과하고, GOLDEN.lock 검증 테스트가 있다

## 1주차: 대상 시스템과 시나리오
- [ ] 샘플 서비스 2~3개 + Loki + Prometheus를 docker-compose로 기동
- [ ] 장애 5종 주입 스크립트: 느린 쿼리, 커넥션 풀 고갈, 잘못된 배포, 외부 API 타임아웃, 메모리 누수
- [ ] 시나리오별 정답 라벨 작성 (사람이 직접. AI는 초안만 제안)
- [ ] 시나리오별 스냅샷 캡처 (`make capture`), `make lock-golden`
- 완료 기준: 시나리오 5개가 스냅샷과 라벨을 갖고, GOLDEN.lock이 생성되어 있다

## 2주차: 에이전트 루프 v0
- [ ] 모델 게이트웨이 (`agent/gateway`): 재시도, 타임아웃, 토큰·비용 계측
- [ ] 루프 직접 구현: 최대 스텝, 토큰 예산, 시간 상한
- [ ] 툴 3개: `search_logs`, `get_metrics`, `get_recent_deploys` (순수 함수 + 스키마. MCP 서버 래퍼를 둘지 결정해 기록)
- [ ] 데이터 소스 어댑터: 실시간 스택과 스냅샷을 같은 인터페이스로
- [ ] 모든 단계를 JSON 트레이스로 저장
- 완료 기준: CLI로 시나리오 하나를 스냅샷 위에서 돌려 리포트가 나온다

## 3주차: 평가 하네스와 베이스라인
- [ ] 시나리오 러너 (시나리오당 3~5회 반복)
- [ ] 지표: 원인 카테고리 일치, 핵심 근거 적중, 스텝 수, 토큰 비용, 지연
- [ ] 고정 파이프라인 베이스라인 (조회 순서 고정 후 모델 1회 호출)
- [ ] 첫 비교표: 베이스라인 vs 에이전트 v0
- 완료 기준: `make eval` 한 번으로 비교표가 나온다. 건당 비용을 실측해 예산을 보정한다

## 4주차: 툴과 컨텍스트 개선
- [ ] 로그 툴이 패턴 집계, 샘플, 상세 조회용 ID를 반환
- [ ] 컨텍스트 압축, 가설 노트
- [ ] 시나리오를 10개로 확장 (새 라벨은 사람이 작성)
- [ ] 바꿀 때마다 평가를 돌려 v0 → v1 → v2 지표 변화를 기록
- 완료 기준: 버전별 지표 표가 있고, 비용이 v0 대비 줄었다

## 5주차: 근거 인용과 검증
- [ ] 리포트 스키마 확정 (docs/ARCHITECTURE.md 참조)
- [ ] 툴 결과마다 evidence ID 발급·보관
- [ ] `submit_report` 툴: 제출 시 ID 존재 여부와 발췌문 일치를 코드로 검증, 실패 시 모델에게 되돌림
- [ ] "주장을 근거가 뒷받침하는가"는 LLM 판정을 사람 라벨로 보정
- [ ] 근거가 부족하면 "불확실"로 답하는 동작을 평가에 포함
- 완료 기준: 인용 유효율과 미검증 인용률이 지표에 있다

## 6주차: 서비스 레이어

- [ ] Slack 리포트 (스레드), 동시 실행 수와 건당 비용 상한
- 완료 기준: 장애를 주입하면 Slack에 리포트가 오는 end-to-end 데모

## 7주차: 가드레일과 보안 평가

- [ ] 방어 전후 공격 성공률 비교

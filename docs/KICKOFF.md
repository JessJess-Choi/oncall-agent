# Claude Code로 시작하기

## 1. 준비 (5분)
1. 새 저장소를 만들고 이 키트를 루트에 복사한다. `git init`
2. `.env.example`을 `.env`로 복사해 값을 채운다.
3. 프로젝트용 키는 `ONCALL_ANTHROPIC_API_KEY`로 둔다. 셸에 `ANTHROPIC_API_KEY`를 export하지 않는다. 설정돼 있으면 Claude Code가 구독 대신 API 과금으로 전환된다.
4. API는 구독과 별도로 Console에서 결제한다. 선결제 크레딧으로 시작하고 auto-reload는 꺼둔다.

## 2. 첫 세션 확인
- 저장소 루트에서 `claude`를 실행한다.
- `/context`로 Memory files에 CLAUDE.md가 있는지 확인한다. AGENTS.md는 CLAUDE.md의 import로 함께 로드된다.
- `/permissions`로 .claude/settings.json의 deny 규칙이 보이는지 확인한다.

## 3. 첫 프롬프트 (plan 모드로 시작)

0주차:
```
docs/ROADMAP.md의 0주차 항목을 읽고 구현 계획을 먼저 제시해줘.
확정해야 할 것(언어/프레임워크 등)은 선택지와 추천 이유를 같이 알려줘.
내가 승인하기 전에는 파일을 만들거나 수정하지 마.
```

1주차:
```
docs/ROADMAP.md의 1주차와 docs/SCENARIO_FORMAT.md를 읽고 계획을 제시해줘.
샘플 서비스는 최소 구성으로 제안하고, 장애 주입 스크립트별로 어떤 로그·메트릭 흔적이 남을지 설명해줘.
정답 라벨은 scenarios/labels에 쓰지 말고 docs/drafts/ 아래에 초안으로만 제안해줘.
```

## 4. 역할 분담
| 맡길 것 | 직접 설계하고 리뷰할 것 |
|---|---|
| docker-compose, 장애 주입 스크립트 | 정답 라벨, 평가 지표 정의 |
| 웹훅, 큐, Slack 배선 같은 보일러플레이트 | 툴 스키마와 출력 형식 |
| 테스트 코드, CI 설정 | 컨텍스트 관리 전략 |
| 트레이스 뷰 같은 UI | 인용 검증 규칙, 인젝션 시나리오 |

하네스 핵심부(루프, 컨텍스트, 인용 검증, 평가)는 AI가 코드를 쓰더라도 내가 모든 줄을 설명할 수 있을 때까지 리뷰한다.
면접에서 가치가 있는 것은 코드 양이 아니라 설계 결정과 그 근거다.

## 5. 한도 관리
- 작업 단위가 끝나면 새 세션을 시작하거나 `/clear`를 쓴다.
- 구독 한도는 5시간 세션과 주간 한도가 있고, 채팅과 Claude Code가 함께 쓴다.
- 구현이 몰리는 주(2~4주차, 6주차)에 한도에 자주 걸리면 usage credits나 한 달만 상위 플랜을 고려한다.
- 평가 비용은 3주차에 건당 비용을 실측해서 예산을 보정한다.

## 6. 설정은 필요할 때 하나씩 추가
| 이런 일이 생기면 | 추가 |
|---|---|
| 같은 규칙을 두 번 틀림 | AGENTS.md에 한 줄 추가 |
| 같은 프롬프트나 절차를 반복 | 스킬 (예: 시나리오 추가, 평가 실행) |
| 특정 디렉터리에만 해당하는 규칙 | `.claude/rules/`의 경로별 규칙 |
| 반드시 지켜야 하는 것 | 훅 또는 permission deny |
| 출력이 시끄러운 부수 작업 | 서브에이전트 |

AGENTS.md는 200줄 아래로 유지한다. 길어지면 규칙이나 스킬로 옮긴다.

## 7. 알려진 한계
- `permissions.deny`의 Edit 규칙은 내장 편집 툴 기준이다. 셸 명령으로 파일을 바꾸는 경로는 별도로 막지 않으므로, 최종 방어선은 평가 러너의 GOLDEN.lock 검증이다.
- 훅이나 서브에이전트 같은 실행 장치는 Copilot으로 그대로 옮겨지지 않는다. 공유되는 것은 AGENTS.md 같은 지침 파일이다.

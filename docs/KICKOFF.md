# Claude Code로 시작하기

## 1. 준비 (5분)
1. 새 저장소를 만들고 이 키트를 루트에 복사한다. `git init`
2. `.env.example`을 `.env`로 복사한다. 1단계는 모델 키가 필요 없으니 비워둬도 된다.
3. 셸에 `ANTHROPIC_API_KEY`를 export하지 않는다. 설정돼 있으면 Claude Code가 구독 대신 API 과금으로 전환된다. `claude` 실행 후 구독 계정으로 로그인되어 있는지 확인한다.
4. API 결제는 2단계를 시작할 때 한다. Console에서 선결제 크레딧을 사고 auto-reload는 꺼둔다. 1단계에서는 하지 않는다.

## 2. 첫 세션 확인
- 저장소 루트에서 `claude`를 실행한다.
- `/context`로 Memory files에 CLAUDE.md가 있는지 확인한다. AGENTS.md는 CLAUDE.md의 import로 함께 로드된다.
- `/permissions`로 .claude/settings.json의 deny 규칙이 보이는지 확인한다.

## 3. 첫 프롬프트 (plan 모드로 시작)

0주차:
```
docs/ROADMAP.md의 0주차 항목을 읽고 구현 계획을 먼저 제시해줘.
확정해야 할 것(언어/프레임워크 등)은 선택지와 추천 이유를 같이 알려줘.
내가 승인하기 전에는 파일을 만들거나 수정하지 마.
```

1주차:
```
docs/ROADMAP.md의 1주차와 docs/SCENARIO_FORMAT.md를 읽고 계획을 제시해줘.
샘플 서비스는 최소 구성으로 제안하고, 장애 주입 스크립트별로 어떤 로그·메트릭 흔적이 남을지 설명해줘.
정답 라벨은 scenarios/labels에 쓰지 말고 docs/drafts/ 아래에 초안으로만 제안해줘.
```

2주차 (러너):
```
docs/ROADMAP.md의 2주차와 docs/ARCHITECTURE.md의 러너 인터페이스를 읽고 계획을 먼저 제시해줘.
러너는 빈 임시 디렉터리에서 실행하고 허용 툴은 oncall MCP 툴로만 제한해야 해.
claude -p 에 쓸 플래그는 공식 문서(headless, CLI reference)에서 확인하고 근거를 알려줘. 기억에 의존하지 마.
승인 전에는 파일을 만들거나 수정하지 마.
```

## 4. 2주차 이해 단계 (코드를 쓰기 전에)
툴 서버가 만들어지면, 러너를 만들기 전에 대화형 Claude Code에 서버를 연결해서 시나리오 한 건을 직접 조사시켜 본다.
- 어떤 툴을 어떤 순서로 부르는가
- 툴 결과를 보고 다음 선택이 어떻게 달라지는가
- 어디서 막히거나 같은 조회를 반복하는가

메모를 docs/notes/에 남겨두면 4주차 툴 개선과 2단계 루프 설계의 출발점이 된다.

## 5. 역할 분담
| 맡길 것 | 직접 설계하고 리뷰할 것 |
|---|---|
| docker-compose, 장애 주입 스크립트 | 정답 라벨, 평가 지표 정의 |
| 웹훅, 큐, Slack 배선 같은 보일러플레이트 | 툴 스키마와 출력 형식, RunResult 인터페이스 |
| 테스트 코드, CI 설정 | 러너 격리 방식, 가드레일 |
| 트레이스 뷰 같은 UI | 인용 검증 규칙, 인젝션 시나리오 |

하네스 핵심부(툴 서버, 인용 검증, 평가, 러너 격리, 2단계의 루프)는 AI가 코드를 쓰더라도 내가 모든 줄을 설명할 수 있을 때까지 리뷰한다.
면접에서 가치가 있는 것은 코드 양이 아니라 설계 결정과 그 근거다.

## 6. 한도 관리
- 작업 단위가 끝나면 새 세션을 시작하거나 `/clear`를 쓴다.
- 구독 한도는 5시간 세션과 주간 한도가 있고, 채팅과 Claude Code가 함께 쓴다. 1단계에서는 평가 실행도 같은 한도를 쓴다.
- 평가를 본격적으로 돌리기 전에 2주차에 소모량을 재서 시나리오 수와 반복 횟수를 정한다.
- 한도에 자주 걸리면 평가 반복 횟수를 줄이거나, 한 달만 상위 플랜 또는 사용량 크레딧을 고려한다.

## 7. 2단계 시작 조건
- 1단계 8주차 완료, 또는 1단계가 8주를 넘기면 6~8주차의 서비스 데모와 UI를 줄이고 착수한다.
- 시작 날짜를 달력에 적어둔다. "나중에"로 남기지 않는다.
- 시작할 때 API를 준비한다: Console 가입, $10~20 선결제, 키 발급, `.env`의 `ONCALL_ANTHROPIC_API_KEY`.
- 첫 루프를 돌려 건당 비용을 확인하고, 그 숫자로 시나리오 수와 모델(Haiku/Sonnet)을 정한다.

## 8. 설정은 필요할 때 하나씩 추가
| 이런 일이 생기면 | 추가 |
|---|---|
| 같은 규칙을 두 번 틀림 | AGENTS.md에 한 줄 추가 |
| 같은 프롬프트나 절차를 반복 | 스킬 (예: 시나리오 추가, 평가 실행) |
| 특정 디렉터리에만 해당하는 규칙 | `.claude/rules/`의 경로별 규칙 |
| 반드시 지켜야 하는 것 | 훅 또는 permission deny |
| 출력이 시끄러운 부수 작업 | 서브에이전트 |

AGENTS.md는 200줄 아래로 유지한다. 길어지면 규칙이나 스킬로 옮긴다.

## 9. 알려진 한계
- `permissions.deny`의 Edit 규칙은 내장 편집 툴 기준이다. 셸 명령으로 파일을 바꾸는 경로는 별도로 막지 않으므로, 최종 방어선은 평가 러너의 GOLDEN.lock 검증이다.
- 훅이나 서브에이전트 같은 실행 장치는 Copilot으로 그대로 옮겨지지 않는다. 공유되는 것은 AGENTS.md 같은 지침 파일과 MCP 툴 서버다.
- 구독 로그인으로 `claude -p`를 쓰는 방식은 정책이 바뀔 수 있다. 공식 도움말은 구독 한도 정책을 다시 정리하겠다고 예고했고, 스크립트용 호출은 앞으로 API 키를 쓰는 모드가 기본이 될 예정이라고 안내한다. 막혀도 툴 서버, 시나리오, 평가는 그대로 쓰이게 설계한다.
- 이 키트의 플래그와 설정 문법은 공식 문서 기준으로 적었지만 실제 환경에서 실행해 검증한 것은 아니다. 첫 실행에서 확인한다.
